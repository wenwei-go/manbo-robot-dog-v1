# 曼波机器狗 V1 引脚与存档核对

核对日期：2026-11-12。硬件依据：[曼波小狗原理图.pdf](曼波小狗原理图.pdf)（V1.0，图内更新日期 2026-11-12）；软件依据：`main@b22a3d1`、`feature/add-CV@aeebeca` 以及本地 `CubeMX+Keil/源码` 存档。

## 1. 实物接线目标

下表方向均以 STM32 为参照；RF/RB/LF/LB 分别为右前、右后、左前、左后，M 为尾巴。

| 功能/网络 | STM32 引脚 | 外设功能 | 接口对应 | 软件接口 |
|---|---|---|---|---|
| RF 右前腿 | PA0 | TIM2_CH1 | 舵机排针 2 | `Servo_SetAngle3` |
| RB 右后腿 | PA1 | TIM2_CH2 | 舵机排针 4 | `Servo_SetAngle4` |
| M 尾巴 | PA2 | TIM2_CH3 | 舵机排针 6 | `Servo_SetAngle5` |
| LB 左后腿 | PA3 | TIM2_CH4 | 舵机排针 8 | `Servo_SetAngle2` |
| LF 左前腿 | PA7 | TIM3_CH2 | 舵机排针 10 | `Servo_SetAngle1` |
| OLED SCL | PB6 | 软件 I2C，开漏输出 | H3-1 | `OLED_SCL` |
| OLED SDA | PB7 | 软件 I2C，开漏输出 | H3-2 | `OLED_SDA` |
| 蓝牙 U3_TX | PB10 | USART3_TX | BLUE-2，接模块 RX | `huart3` |
| 蓝牙 U3_RX | PB11 | USART3_RX | BLUE-3，接模块 TX | `huart3` |
| 语音 U1_TX | PA9 | USART1_TX | H2-7，经 SW2 | `huart1` |
| 语音 U1_RX | PA10 | USART1_RX | H2-6，经 SW3 | `huart1` |
| 下载/调试 | PA13 / PA14 | SWDIO / SWCLK | 核心板 SWD | 保留 SWD |

- 舵机排针奇数脚 1/3/5/7/9 为 +5V，旁边五针为 GND。
- OLED H3-3 为 VCC，H3-4 为 GND；BLUE-4 为 GND，BLUE-5 为 VCC，BLUE-1/6 未连接。
- 原理图 VCC 网络接核心板 V3.3；+5V 为独立电源网络。舵机和主控共地。
- 蓝牙使用 **STM32 USART3，115200、8N1、无流控**。电脑的 COM 号由配对结果决定，与 MCU 的 USART 编号没有对应关系。
- 修复分支启用 USART1，暂按 115200 8N1 接收单字节动作指令；语音模块的具体型号、串口波特率及是否使用单字节输出，需要结合模块配置核实。原固件保留了语音命令定义，但未启用原理图中的 USART1。

## 2. 原固件差异

| 项目 | 存档代码 | 原理图要求 |
|---|---|---|
| 四腿 PWM | TIM1 PA8/PA9/PA10/PA11 | TIM2 PA0/PA1/PA3 + TIM3 PA7 |
| 尾巴 PWM | TIM2_CH1，PA15，部分重映射 | TIM2_CH3，PA2，默认映射 |
| OLED | PB8/PB9（包含驱动中的硬编码） | PB6/PB7 |
| 蓝牙 | USART3 PB10/PB11，115200，DMA RX Channel3 / TX Channel2 | 一致 |
| 语音 | 未初始化 USART1；PA9/PA10 被配置成舵机 PWM | PA9/PA10 专用于 USART1 |
| 舵机读取 | 1/3/4 的读取通道与写入通道不同；1/3 未还原反向角度 | 读写必须对应同一物理通道和逻辑角度 |
| 蓝牙多字节 | 每批仅处理首字节，其余丢弃 | 单字节指令应逐字节解析 |

原 `Servo.c` 中的腿位注释与 `Servo.h` 互相矛盾。这里以对外头文件约定固定编号：1=左前、2=左后、3=右前、4=右后、5=尾巴，动作层继续使用该编号；原来 1/3 的角度反向关系保留，实际安装方向和中位仍需上板验证。

## 3. 已有工作与分支安排

- `main`：STM32F103C8T6 HAL + CubeMX + Keil 工程；OLED 表情、五舵机动作状态机、USART3 DMA 空闲接收。
- `feature/add-CV`：增加 MediaPipe 手势识别，通过蓝牙发送 `0x21/0x22/0x23`；保存原理图、[通信协议](../通信协议.md)和本核对表。
- 从 `feature/add-CV` 新建 `fix/hardware-pins-usart3` 修正固件，并同步 `.ioc`、驱动、串口中断与协议说明。
- 本地 `CubeMX+Keil/源码` 是参考存档，保留原样。新 Git 工作副本位于它的同级目录 `manbo-robot-dog-v1`。

Keil 工程实际编译的自定义驱动为 OLED、OLED_Data、Servo、Move。BH1750、MPU6050、DHT11、Key 等为未接入主程序的历史文件，原理图也未提供这些模块的接线；不能据此猜测引脚。尤其旧 `bsp_dht11.c` 会启停 TIM3，后续启用前必须迁移其微秒延时，避免影响 PA7 舵机 PWM。

## 4. 修复分支实现对应

| 检查项 | 实现 |
|---|---|
| 五路舵机 GPIO/PWM | `Core/Src/tim.c`：TIM2 默认映射 PA0～PA3，TIM3_CH2 默认映射 PA7；两组均为 72 MHz / 72 / 20000 = 50 Hz |
| 舵机逻辑编号 | `MyDriver/Servo.c`：1=TIM3_CH2、2=TIM2_CH4、3=TIM2_CH1、4=TIM2_CH2、5=TIM2_CH3；启动前设 90° 中位，限制 500～2500 us 脉宽，读取使用对应通道并还原逻辑反向 |
| OLED GPIO/驱动 | `Core/Inc/main.h`：PB6/PB7；`gpio.c`：开漏；`OLED.c` 通过统一的引脚宏访问 |
| 蓝牙 | `usart.c`：USART3 PB10/PB11，115200 8N1，RX 循环 DMA Channel3；`stm32f1xx_it.c` 保留 USART3/DMA IRQ |
| 语音 | `usart.c`：USART1 PA9/PA10，115200 8N1，PA10 上拉避免未接模块时悬空，USART1 IRQ；`RobotControl.c` 单字节接收 |
| CubeMX / Keil | `.ioc` 同步外设、引脚、DMA 模式和中断；`.uvprojx` 加入 `RobotControl.c/.h` |

两组定时器提供相同周期，未做相位同步。舵机方向、机械中位和动作负载效果需实物验证；主机测试和编译不能替代上板检查。
